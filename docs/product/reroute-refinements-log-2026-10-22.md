# Reroute refinements log

**Status:** Implemented on 2026-10-22 for team review. Built with Claude Code assistance (see the [AI-use log](../team/ai-use-log.md)). No participant has tested these refinements and nothing has been deployed, so nothing below is user evidence.

This log records what the [Reroute](../../apps/plan-b-mvp/README.md) app (formerly Plan B MVP) builds from the "Refinements" section at the end of the [prototype ideas](../design/prototype_ideas.md), together with the decisions the project lead gave when the work was assigned. It follows the [v3 feature log](mvp-v3-feature-log-2026-10-21.md) and the [v2 feature log](mvp-v2-feature-log-2026-10-21.md). The refinements are the student's own design proposals, not participant findings, and this log does not add any interview evidence. Style rules still come from the [design system brief](../design/design-system.md).

## Decisions and deviations

- **Added places limit:** The limit is 10 added places plus Home and Work/Uni, which is one reading of "max 10"; changing the constant `MAX_CUSTOM_PLACES` changes it.
- **Settings migration:** Home and Work values saved by v3 are carried into the new `saved_places` list on first load, with Work defaulting to the University of Queensland address as before. The old keys are not written again.
- **Server search type:** The app no longer sends the `planb` search type; the default is `regular`. The server treats a `planb` request from an older cached copy of the app as a regular search instead of rejecting it, and rejects any other unknown type.
- **Hero text:** The hero headline was reworded (see the weather row above) and the hero CO2 chip was removed; neither was in the refinements text.
- **CO2 field setting:** The existing "CO2 emissions" card toggle in Settings now also hides the new line, badge and summary on results, so someone who switched CO2 off does not see it return.
- **Month and week boundaries:** Months and weeks use Brisbane time. Earlier versions used UTC for the monthly totals.
- **Logo:** The mark is unchanged, so no PNG icons were regenerated.
- **Scope shift:** None. No new external service or API is used; the refinements only reorganise and extend the front end and remove one server search type.

## Known issues

- The "Lowest CO2" badge makes the CO2 line wrap onto two lines on narrow phones.
- A toast no longer blocks taps, but it can briefly cover the bottom of a sheet.
- The weekly streak labels show every second week to avoid overlap at 360 px.
- The "km not driven" figure rests on the car settings in Settings (8 L/100 km by default), which a new user may not have changed.
- The app shell is cached first, so `VERSION` in `sw.js` must still be bumped on every deploy.

## Review fixes (2026-10-22)

A review of the teammate's merged "Further refinements" (cycle options, home shortcut, legal pages, caps, Google Maps migration) was done with Claude Code (lead Claude Opus 5.5, one Claude Sonnet subagent). Each item below is an issue found and the fix. The reviewed behaviour was checked in headless Edge at 430 and 360 px, dark and light, and with the offline tests; nothing was tested with participants or on a real phone.

- Maps never drew: the Google Maps script URL used `loading=async` without a callback, so `google.maps.importLibrary` did not exist when the script loaded and every map stayed on its shimmer. The loader now uses a callback and imports the `maps` and `marker` libraries.
- Map failures were not handled well: a missing browser key, a blocked or slow script, a rejected key (`gm_authFailure`) or a drawing error left plain text or a stuck shimmer. Every map slot now shows a design-system warning banner (steps and directions text stay usable), the zoom and expand buttons are hidden, nothing rejects unhandled, and failures are not retried for 30 seconds (a rejected key until reload).
- Map clean-up left Google listeners and the all-routes info window behind when a sheet or screen closed. `disposeMap` now clears listeners, overlays and the info window, and removed maps are dropped.
- Dark map styling followed only the saved theme choice, so "Auto" on a light system kept a dark map. It now follows the theme in force.
- Google's own camera and compass control sat under our zoom buttons. `cameraControl` and `rotateControl` are switched off.
- In the full-screen map the Home shortcut covered the zoom-in button. The map buttons now start below the shortcut when expanded.
- Pinch-zoom marker drift (spec item 4) was checked and is not present with Google markers: markers are native map overlays, the marker elements carry no CSS transition or animation, and vehicle moves are plain position updates. The dead Leaflet-era CSS (`.veh*`, `.tev*`, `.me*`, `.pin*`) was removed.
- Cycle options had no `co2_kg`, so the CO2 sort, the Lowest CO2 badge, the greenest-option summary, trip logging and the dashboard skipped or misread them. They now have 0 kg tailpipe CO2 with an honest note ("No tailpipe emissions; charging and manufacturing not counted", manufacturing only for the push bike), and the wording says "tailpipe" wherever a saving is claimed.
- The push-bike time was an invented 12 km/h. It now uses Google's own cycling duration (12 km/h only if Google sends none). E-scooter and e-bike keep assumed 15 and 20 km/h, labelled as assumptions on the card, sheet and Settings.
- The push bike was not limited to short trips. It is now offered only up to 5 km (`PUSH_BIKE_MAX_KM`), with a note on the results when it is hidden. It stays off by default.
- E-scooter and e-bike were on by default, adding a Google request and unchecked cards to every search. They now default to off like the push bike (a browser that already saved its settings keeps the saved choice).
- Each search made three cycle options from two routes (up to six near-identical cards). It now makes one option per mode from the first cycling route.
- The cycle step list was one long disclaimer. It now lists Google's cycling steps and the disclaimer moved to an info banner on the detail sheet.
- "Start directions" was hidden for cycle options (empty `nav`). Live directions are now built from the cycling steps and the demo simulation, Re-plan and the screen wake lock work for them.
- Panic mode could recommend an unchecked cycle option (0 walking minutes made it look easiest). Cycle options are now excluded from the recommendation, as Uber already was, unless nothing else exists.
- Cycle cards read "?" for cost and "See why it doesn't fit". They now say "Not checked", "Check details before choosing" and "Chosen, cost and access not checked".
- The detail sheet compared with driving using a null CO2 saving, which printed "−0 kg". It is now null-safe.
- The journey screen's "Ways to travel" line left out the scooter and bike modes, and the dashboard showed the raw kind (`scooter`). Both now use the proper labels, and the dashboard footnote says scooter and bike savings are tailpipe only. The mode tile also has the scooter and bike colours.
- The Home shortcut was 40 px tall, overlapped the Settings gear at 430 and 360 px and the Exit button in panic mode, and also showed on the home screen over Settings and sheets. It is now 44 px with a fixed width, the header makes room for it, it only shows away from the home screen, and it has hover and pressed states. Going home also resets a finished panic answer.
- Legal pages had no Back button, and leaving one replaced its history entry so browser Back skipped it. They now have a Back button, in-app Back uses browser history for pages the app opened, and going home adds a history entry so Back returns to the page you left. Deep links `/terms`, `/privacy` and `/about` work online and offline.
- Legal page text did not match the code in several places. Fixed: the service worker also caches read-only API answers (including typed address suggestions); the server console logs the IP address and URL of every request unless `PLANB_QUIET=1`; push subscriptions store origin and destination text, place ID, deadline, line names and route IDs; ride posts are removed about 30 minutes after departure and keep joiners' nicknames; weather uses the device location when allowed; Google Maps JavaScript and Google Fonts are listed separately; the browser map key is handed to every visitor; push-bike limits and tailpipe-only CO2 are stated. The "review before release" notes were kept.
- The three legal links on the home screen were 36 px tall. They are now 44 px.
- The daily address-suggestion cap told people "daily limit of live searches". It now says address suggestions and to type the full address.
- A shared browser and server Google key was silently allowed. The server now prints a start-up warning (never the key) when `MAPS_BROWSER_API_KEY` equals `MAPS_API_KEY`, with a test.
- The README and `infra/plan-b-mvp/README.md` were updated for the maps failure state, cycle options, the home shortcut, the service worker, logging (`PLANB_QUIET`) and the key warning, and the service worker cache was bumped to `planb-reroute-3` so installed copies pick up the changes.
- Checked and unchanged: tolls are only requested while "My own car" is on (the field mask drops the toll field otherwise), the daily 429 message shows as a warning banner, and 50 searches a day shared by everyone is low for a demo but was requested by the team, so it was not changed.
- Still not verified: a real two-finger pinch on a phone (a synthetic two-touch pinch and a programmatic zoom were used), a separate referrer-restricted browser key (the shared server key was used locally), Google's deprecation warning for `google.maps.Marker` (still supported; moving to `AdvancedMarkerElement` needs a Cloud map ID and would change the dark styling), and e-scooter or e-bike routing (Google has none, so both use a cycling route; three real searches on the shared key confirmed the cycling data, durations and steps).

## Home button follow-up (2026-10-23)

Done with Claude Code (Claude Opus 5.5) at the project lead's request. This was a developer check only; no participants were involved.

- **Problem:** The Home shortcut was one floating button laid over every screen. It did not move with the page transitions. It also looked different from the other header buttons (a 12 px radius, a raised surface and a shadow), and each header had to reserve 96 to 108 px of empty space for it.
- **Fix: one shared button built into each screen.** The button is now part of each screen's own header, so it slides with that screen, with Settings and with sheets. It has the same height, radius, surface and hover and pressed states as the Settings gear. A shared `homeButton` helper in `app.js` adds it in these places:
  - every navbar with a Back button;
  - the Journey disrupted? header, next to Exit;
  - the live-directions banner;
  - the Settings header, beside Done;
  - every sheet header, beside the close button.

  Settings and sheets show it only away from the home screen. The floating button, `updateHomeShortcut`, the `has-home-shortcut` padding rules and the expanded-map offset for the zoom buttons were removed.
- **Fix: narrow screens.** Below 360 px the button shows only its icon, keeping its accessible name. On the Journey disrupted? header the same happens below 370 px, so "Fastest way now" stays on one line.
- **Deviation:** The full-screen expanded map covers the page header, so it no longer shows the Home button. Closing the map with its own button brings the header back.
- **Cache:** The service worker cache was bumped to `planb-reroute-4` so installed copies pick up the change.
- **Checked** in Chrome at a 480 px app column and in 430, 390, 375, 360 and 320 px frames:
  - the journey screen, Impact dashboard, Shared rides, Terms, Privacy, About and Journey disrupted?;
  - Settings opened from the home screen and from another screen;
  - the Translink alerts sheet, and the add-place sheet above Settings.

  Halfway through a transition the button sat at the incoming page's offset. Pressing it from a sheet open above Settings closed both and returned home. No header overflowed. The live-directions header was checked with mock banner markup, not a real route. The 263 offline tests pass. The change was not tried on a real phone, in the light theme or with a screen reader.
