## Decisions and deviations

- **Prices:** A single assumed price is used for both operators because neither publishes a current Brisbane price. The team should open both apps, note the prices with the date, and either change the defaults (`HIRE_DEFAULTS` in `live_routes.py` and `DEFAULT_SETTINGS.hire` in `app.js`) or enter them in Settings.
- **Radar source:** RainViewer was the only free radar source found that allows use in an educational web app. The Bureau of Meteorology offers no public radar tile service for third parties, and its FTP terms do not allow supplying images to others. RainViewer does not guarantee availability.
- **Side menu contents:** The request named Settings, Demo mode and the Impact Dashboard. Weather, Translink alerts, Shared rides, Share, Install and the three information pages were added so the menu is the one place for every secondary screen.
- **Legal pages:** The Terms, Privacy Policy and About / Data Sources pages were updated for the new data flows: location asked for when Plan a trip opens, place IDs sent to Google when a place is tapped on the map, radar images loaded directly from RainViewer, the Lime and Neuron links, the assumed hire prices and the placeholder profile.
- **Service worker:** `VERSION` in `sw.js` was bumped to `planb-reroute-5` so installed copies fetch the new files.

## Known issues

- **Maps not shown in the developer check:** The local check used the server key as the browser map key (in the test process only), and Google rejected it for Maps JavaScript on both local addresses tried. So the map picker, the rain radar map, the long-press and the pin dragging were checked by code review and by a direct check of the radar tile address, not on screen. The team should check them with the deployed browser key, on a phone.
- **Long-press on phones:** The press timer, pinch cancel and the click that follows a press were written for iOS Safari and Android Chrome but not tried on either.
- **Place lookups count even when cached:** A repeat tap on the same place counts towards the hourly and daily limits although the server answers from its cache. This errs on the safe side.
- **Location on opening Plan a trip:** People who decline location see the permission request again each time their browser asks; the app cannot change that.
