# Reroute (formerly Plan B MVP)

Reroute (formerly Plan B MVP; v3 plus the 2026-10-22 refinements) is a student prototype, run locally or from a prepared deployment configuration, that plans everyday trips with public transport first, shows the CO2 you avoid compared with driving, and helps a traveller choose a practical alternative when a public-transport journey is disrupted. It is an installable web app (PWA) with a Flask server, a dark editorial look taken from the [design system brief](../../docs/design/design-system.md), live Translink vehicle positions, in-app directions, weather, traffic, background disruption notifications and an investor demo mode. It implements the "Further features" section of the [prototype ideas](../../docs/design/prototype_ideas.md) on top of the v2 features, and the "Refinements" section at the end of the same document (the [refinements log](../../docs/product/reroute-refinements-log-2026-10-22.md) maps each one to what was built). Section 9 of the 22/10/2026 refinements ("Further bug fixes/additions") is mapped in the [further fixes log](../../docs/product/reroute-further-fixes-log-2026-10-23.md), and the "Refinements 23/10/2026" section in the [refinements log for 23/10/2026](../../docs/product/reroute-refinements-log-2026-10-23.md). The separate [interview scenario](demo.html) preserves the prepared, fictional Bus 412 exercise; it keeps the name Plan B because that is the version the interview material refers to. The [scope and evidence trail](../../docs/product/mvp-scope-2026-10-20.md) links all 21 de-identified prototype interview records, the [v2 feature log](../../docs/product/mvp-v2-feature-log-2026-10-21.md) maps the earlier ideas, and the [v3 feature log](../../docs/product/mvp-v3-feature-log-2026-10-21.md) maps each v3 rule and feature to what was built and what remains untested.

**Status:** implemented on 2026-10-21 (v3) and refined on 2026-10-22 (the rename to Reroute and the refinements) with Claude Code assistance for team review. No participant has tested it, nothing has been deployed, and nothing here establishes adoption, live-data accuracy or willingness to pay.

## The name change: what keeps the old name

The app is called Reroute everywhere a person can see it: the page title, the home-screen name, the logo wordmark, the install and share sheets, the push notification titles and text, toasts, the server start-up message and user-visible server errors, and the User-Agent sent to external services. These intentionally keep the old name so saved data, links and deployment configuration keep working: the folder `apps/plan-b-mvp/` and the `infra/plan-b-mvp/` folder, the `planb.*` localStorage keys (saved settings, trips and watches), the `PLANB_*` environment variables, the `planb-` prefix of the service-worker cache name (the cache itself is now `planb-reroute-1`), the Python module names and the internal `planb` extension key, the notification tag prefixes, the `mailto:planb-demo@example.invalid` default VAPID contact, and the fictional interview scenario (`demo.html`, `demo.js`, `styles.css`). The logo mark (a direct route broken by a disruption, with the route curving around it) is unchanged, so the favicon and icon files were not regenerated.

## Run locally

Prerequisites: Python 3.13 and a Google Cloud API key. v3 is no longer standard-library only: it needs Flask, pywebpush (with `cryptography`), segno and gunicorn, listed in `requirements.txt`. There is still no build step for the front end. From this directory:

```bash
pip install -r requirements.txt
python server.py
```

Then open `http://127.0.0.1:8000`. For interactive maps, set `MAPS_BROWSER_API_KEY` to a separate key restricted to `http://127.0.0.1:8000/*` and `http://localhost:8000/*`, with Maps JavaScript API only. The optional `HOST` and `PORT` environment variables change where it listens (default `127.0.0.1` and `8000`). On a phone-sized screen the app fills the screen with safe-area insets; on desktop it is a centred column up to 480 px wide. On Windows, `python` must be a real Python install: the Microsoft Store shortcut that Windows puts on the PATH by default does not run scripts, so use the full path to your `python.exe` (or `py`) if `python server.py` prints a Store message instead of starting the server.

Install and Web Push need a secure origin: `http://localhost` and `http://127.0.0.1` work on the same machine, but a phone needs HTTPS (see [`infra/plan-b-mvp/README.md`](../../infra/plan-b-mvp/README.md)). The first start downloads the Translink static GTFS zip (about 35 MB) in a background thread and builds a cached index of about 1.3 MB (1,211 routes and 12,861 stops at the check on 2026-10-21); this took about 20 seconds on the developer machine, and searches never wait for it. Since the offline area download (2026-10-26) the zip is kept as `data/gtfs/SEQ_GTFS.zip` so offline timetables can be cut from it; an older install that has only the index downloads the zip once in the background. The cache is stored in `data/`, which is git-ignored.

### API key lookup

The server looks for the Google key in this order and uses the first one it finds:

1. the `MAPS_API_KEY` environment variable;
2. a `.env` file in `apps/plan-b-mvp/`;
3. a `.env` file in `apps/prototype-6-2026-09-23/` (the team's existing key).

`.env` files are git-ignored. Keep the server key on the server and never commit either key. The interactive map uses a separate `MAPS_BROWSER_API_KEY`, which is intentionally public to browsers and must be restricted by HTTP referrer to the exact development and deployment origins and by API to Maps JavaScript API only. Never put `MAPS_API_KEY` in the browser, and never set `MAPS_BROWSER_API_KEY` to the same value: the server prints a console warning at start-up if the two keys are equal, because `/api/config` hands the browser key to every visitor. Without the server key, Google-powered features (routes, places, fuel prices, car parks and elevation) are unavailable; without the browser key, or if Google fails to load or rejects the key, each map slot shows a warning banner instead of a map while the steps, results and directions text remain fully usable.

Google requires route content to be shown on a Google map. The app therefore uses Google Maps JavaScript for every route map and leaves Google's automatically rendered logo and attribution visible; it does not overlay Google routes on OpenStreetMap. Where Google Places or Routes content appears outside a map, the app also shows the permitted “Google Maps” text attribution in a high-contrast, non-translated label.

### Google APIs

| API | Needed for | Status on the team key (checked 2026-10-21) |
| --- | --- | --- |
| Routes API | Public-transport, driving and cycling routes, walking steps, tolls (only while "My own car" is on), map geometry, step-by-step maneuvers for in-app directions | Required; enabled and verified |

Place Details was added on 2026-10-23 and its icon fields on 2026-10-26 (still one Place Details Pro request); neither has been tried on the team key |
| Elevation API | Uphill and downhill metres for walking sections | Optional; it worked on the team key during v3 testing (a first search made four Elevation requests), so the v2 statement that it was not enabled is no longer correct. Google bills requests per API. Set a suitable quota or budget in Google Cloud before shared use. See Google's [Routes API setup](https://developers.google.com/maps/documentation/routes/get-api-key), [transit routing](https://developers.google.com/maps/documentation/routes/transit-route), [usage and billing](https://developers.google.com/maps/documentation/routes/usage-and-billing) and [attribution policy](https://developers.google.com/maps/documentation/routes/policies).

## Data sources and what is sent where

| Service | What it provides | What is sent |
| --- | --- | --- |
| Google Routes API (via this server) | Transit, driving and cycling routes, durations, tolls (only while "My own car" is on), fares when returned, route and step geometry, maneuvers | Origin, destination and departure time for each search |
| Google Places API (New) (via this server) | Address suggestions, the name, address and category icon of a place tapped on the map, fuel prices near the start and car parks within 800 m of the destination | The partly typed address with a random session token and an approximate bias location (current location or Brisbane), the place ID of a tapped place, and coordinates near the start and the destination |
| Google Elevation API (via this server) | Elevation for walking sections, when enabled on the key | Sampled coordinates along walking paths |
| Translink SEQ static GTFS (`gtfsrt.api.translink.com.au/GTFS/SEQ_GTFS.zip`, no key, CC BY 4.0) | Routes, trips and stops, used to map each Google transit step to exact route IDs, stop IDs and (where possible) trip IDs, and the scheduled timetable of an offline area (`GET /api/offline/transit`). The zip (about 35 MB) is kept on the server's disk; an offline area's stops, trips and route shapes are cut from it on request | A plain download request from this server, at start and when the cache is older than 7 days; nothing about the traveller is sent |
| OpenStreetMap via the Overpass API (`overpass-api.de`, falling back to `overpass.kumi.systems`; no key; ODbL 1.0, credited as "© OpenStreetMap contributors") | The offline base map and the road and path network for offline walking, cycling and driving routes (`GET /api/offline/map`): routable roads and paths with one-way and access flags, ferry lines, railways, water, larger green areas, suburb and area names and significant places such as stations, hospitals and universities. Google Maps content is never stored offline | Only the area's bounding box, in one query from this server with the User-Agent `Reroute-student-MVP`. Fetches run one at a time, at most 60 a day, and each area is cached on the server for a day |
| Translink SEQ GTFS-Realtime alerts and trip updates (no key) | Service alerts, delays and cancellations, cached for 60 seconds (trip updates 30 seconds) | A plain feed request from this server; no trip details are sent |
| Translink SEQ GTFS-Realtime VehiclePositions (no key) | Vehicle locations (about 800 to 1,000 vehicles in the developer check; bearing is usually absent), cached for 15 seconds | A plain feed request from this server |
| Open-Meteo forecast API (no key) | Weather for the home widget, the weather page (24 hours, 7 days and the next hour's rain in 15-minute steps after the radar, a model forecast that Open-Meteo interpolates from hourly data for Australia) and walking warnings, cached for 10 minutes per cell of about 1 km | Coordinates of the start rounded to three decimals (about 100 m), from this server |
| RainViewer weather maps API (no key) | The rain radar on the weather page: the last two hours of composite radar, tiles up to zoom 7 (enlarged above that). RainViewer has offered no future (nowcast) frames to free users since 1 January 2026 | Requested directly by the browser; RainViewer receives the IP address and the map area viewed. Free for personal and educational use; credited on the page |
| Open-Meteo elevation API (fallback) | Elevation from a 90 m Copernicus terrain model | Sampled coordinates along walking paths |
| QLDTraffic GeoJSON API (public key) | Road events used to estimate driving delays, cached for 5 minutes | A plain request from this server; no trip details are sent |
| Browser push services (the endpoint of each browser, for example Google, Mozilla or Apple) via Web Push | Delivery of background disruption notifications | An encrypted payload (title, text and a link) from this server to the subscription endpoint, only for travellers who turn on background alerts |
| segno (library, no external service) | The QR code at `/qr.svg` | Nothing leaves the server |
| Uber universal deep link (`m.uber.com/ul`) | Opens Uber with pickup and dropoff filled in | Pickup and dropoff coordinates, only when the traveller opens the link |
| Lime and Neuron app store listings and websites | "Open Lime" and "Open Neuron" on e-scooter and e-bike options | Nothing from the trip; the App Store, Google Play or the operator's website is opened only when the traveller taps the button |
| Google Maps directions link | Secondary hand-off for the chosen trip | The entered places, only when the traveller opens the link |
| Google Fonts (`fonts.googleapis.com`, `fonts.gstatic.com`) | The Inter typeface used by the design system | Standard font and stylesheet requests from the browser |
| Google Maps JavaScript API | Interactive maps for Google route content; Google's map logo and attribution are kept visible | Standard map, tile and browser requests to Google from the browser, including the category icon of a place tapped in "Choose on map" (from `maps.gstatic.com`) |

The browser stores settings, saved places, recent places, the last trip places, demo settings, watch details, ride-board tokens and the impact history in `localStorage` on that device only, and the service worker keeps a copy of the app files and of recent read-only API answers (alerts, weather, fuel, address suggestions, status, map settings). The server console log records each request (time, IP address and URL, which includes typed suggestion text and weather or fuel coordinates) unless `PLANB_QUIET=1` is set. The server stores the ride board, push subscriptions, VAPID keys, the GTFS index and zip and the offline map cache in `data/`, which is git-ignored.

Offline area sizes measured on 2026-10-26 with the real feeds (developer machine; a small cloud server will be slower): for a dense 6 by 6 km box around the Brisbane CBD (south -27.50, west 152.98, north -27.445, east 153.04), the Overpass answer was 17.2 MB and took 59 seconds (the main instance was at capacity, so the fallback answered); the server turns it into a 2.85 MB `map` (0.46 MB gzipped; 21,277 ways of which 11,762 are footpaths, 477 rail lines, 16 water features including the Brisbane River as a filled area, 67 green areas, 28 place names and 154 significant places). The `transit` extract for the same box took 5 to 7 seconds and is 2.25 MB for 3 days (0.46 MB gzipped; 262 route variants, 858 stops, 11,792 trips) and 4.8 MB for 7 days (0.82 MB gzipped). Suburban boxes are much smaller: Carindale (6 by 6 km) 0.36 MB and Toowong to Indooroopilly (4 by 4 km) 0.33 MB for 3 days, each in about 5 seconds. A whole pack for the dense box is therefore about 5 MB as JSON, so the contract limits (at most 8 km a side and 40 km², at least 0.5 km a side, 1 to 7 days, inside South East Queensland) were kept; they are in `offline_area.py` and published as `offline_limits` in `/api/status`. Both endpoints answer gzipped JSON when the browser accepts it. Because an Overpass answer can take about a minute, both extracts run in a background job: a request waits up to 40 seconds and otherwise gets HTTP 503 with "Try again in a minute" (and `Retry-After: 60`), and the retry is answered from the finished job or cache. The timetable endpoint also answers 503 while the GTFS zip is still downloading (`offline_transit` in `/api/status` is then "loading", or "unavailable" after a failed download). These figures are developer checks, not participant evidence.

## Features

The mapping from each rule and feature to what was built is in the [v3 feature log](../../docs/product/mvp-v3-feature-log-2026-10-21.md) (v2 features are in the [v2 feature log](../../docs/product/mvp-v2-feature-log-2026-10-21.md)). In summary:

### Look and feel (design system)

- **Design system look:** dark-first editorial layout using the tokens in [`design-system.md`](../../docs/design/design-system.md) (surface layers, subtle 1 px borders, Inter, 16 and 24 px spacing, one accent), with Auto, Light and Dark themes in Settings. The fake phone hardware and status bar of v2 were removed.
- **States and tactility:** pressed state (scale 0.98), accessible focus rings, 44 px minimum tap targets, shimmer skeletons instead of spinners, and fading success and error banners. Animations use only `transform` and `opacity`, and respect the reduced-motion setting.
- **Focus management (WCAG 2.2 AA target):** the side menu, Settings, sheets, pop-ups, a full-screen map and dialogs keep focus inside while open (the screen behind is `inert` and Tab wraps), close with Escape, and return focus to the control that opened them. A screen change moves focus to the new screen's heading. When Journey disrupted? finds an answer, focus moves to the answer, whose accessible name is the whole answer (label, leave time, arrival, deadline line, reason and avoided disruptions), so a screen reader reads it out. Each option card has one tab stop, its body, and its accessible name is its own text rather than a generic "Details for …" label. Status colours meet 4.5:1 for text in both themes (see the contrast fixes in `DESIGN.md`).
- **Clear buttons:** every text, search and address input (From and To, the Journey disrupted? fields, saved places, the place editor, the ride form and the alerts filter) shows a small x once it has text. It is a 44 by 44 px target around a smaller icon, has an accessible name such as "Clear To", keeps focus in the field, closes the suggestions and resets any stored place ID. One helper (`enhanceClear` and `clearInput` in `app.js`) provides it for all fields.
- **Icons and loading:** one set of inline SVG icons instead of emojis; Google Maps is loaded the first time a map appears and the QR image is lazy-loaded.

### Planning and decision support

- **Address suggestions and Choose on map:** every address field shows a dropdown of suggestions while typing, from Places API Autocomplete (New), plus the current location, saved places, recent choices and "Choose on map". The map picker shows Google's places: tap one to choose it (it grows into a large pin in the place's own colour with its Google glyph; its place ID is used and the server looks up its name), or press and hold to drop a pin shaped like the Google Maps pin, with its tip on the spot (its coordinates are used). The pin turns into a circle while it is dragged and bounces back into a pin when it is put down; it is an HTML map overlay, so it needs no Map ID. A chosen suggestion's Google place ID is sent to the Routes API. Requests wait until three characters, are debounced and use session tokens to limit billing.
- **Trip search:** real free-text origin and destination, "Current location" (browser geolocation; From starts as the current location, falling back to the last start point with a note), places chosen on the map, saved places (Home, Work/Uni and any you add), departure time and an optional deadline. To starts empty (except for the demo preset trip); saved places are chips under it and recent places are suggestions.
- **Plan a trip as the main action:** the home screen's single primary (accent-filled) button. Public transport comes first by default, the deadline is optional, and the sort chips re-rank by deadline fit, arrival, cost, walking or CO2. The old "My journey is disrupted" entry and its separate mode were removed; re-planning that avoids disrupted lines (from the in-app watch alert or a push notification) now opens these same results, sorted by best fit, with a note that routes using those lines are flagged.
- **Home screen order:** a header row (the logo and wordmark, which open the side menu; the Impact button; a placeholder profile picture), the hero, Plan a trip, Journey disrupted?, then a Right now group with the weather, Translink alerts and Refresh live data, then the impact summary, shared rides and install and share.
- **Side menu and profile:** the logo opens a menu sliding in from the left with the Impact Dashboard, Weather, Translink alerts, Shared rides, Settings, Demo mode, Share, Install and the information pages; swipe left, tap outside or press Escape to close it. Settings is reached only from here and from contextual links (Ways to travel, Change goal). The profile menu's "Account details" and "Edit profile" show "Feature not available": there are no accounts.
- **Sheets:** every bottom sheet can be dragged down by its grab line or header to close it (it springs back after a short drag), and pop-ups such as a full alert or the map picker open above the sheet underneath. Every Back button says "Back".
- **Transparent ranking and plain-language cards:** sort chips with a one-line explanation, a trade-off sentence per card, a "vs driving" comparison, certainty cues (deadline buffer, live status) and effort cues (walking, climb, transfers). Card fields can be hidden in Settings. When a deadline is set, the Best fit and Public transport first sorts put the options that arrive on time with no disruption first, and Public transport first only reorders those (2026-10-27). An unknown price (no Google fare and no flat fare, Uber, a push bike, or driving with unknown fuel or parking cost) is its own "Price unknown" state rather than a failed budget limit; a known part of the cost that is already over the budget still fails.
- **Elevation gain:** uphill and downhill metres for walking parts of public-transport options, from an elevation service rather than the Routes API.
- **Driving cost, parking and traffic:** fuel plus the Google toll estimate plus parking, with car parks within 800 m of the destination. QLDTraffic events within 150 m of the driving route add an estimated delay (a closure on the route is flagged and blocks the option; a crash, hazard or flood adds 5 minutes; roadworks or a special event add 2; the total is capped at 20 and labelled as an estimate). Google's traffic-aware drive time already includes normal congestion.
- **Uber:** a deep link opens Uber with pickup and dropoff filled in. The app does not show an Uber price and labels rideshare cost as unknown.
- **Map:** Google Maps JavaScript with a dark map style, zoom buttons, fit route, full-screen expand, colour-coded segments (GTFS route colours when matched, dashed walking), pins, car-park pins, traffic incident pins and an overview map of all routes. Google route geometry is shown on Google Maps, whose logo and attribution remain visible on each map; the app uses “Google Maps” text attribution beside route and Places content outside maps.
- **Home shortcut and legal pages:** every screen except the home screen, including live directions, Settings and sheets, has a 44 px Home button at the top right of its own header (so it slides in and out with that screen, and shows only its icon on very narrow screens) that closes sheets, stops live directions (position watcher, timer and screen wake lock) and returns home. Terms of Use, Privacy Policy and About / Data Sources are linked at the bottom of the home screen and also work as deep links (`/terms`, `/privacy`, `/about`) with browser Back and Forward, offline included. Their statements were checked against the code on 2026-10-22 and still carry "review before release" notes.
- **Micromobility estimates:** separate e-scooter, e-bike and push-bike options, all off by default (turn them on in Settings), come from one Google BICYCLE route (the first route Google returns). The push bike uses Google's own cycling duration (an assumed 12 km/h only if Google sends none) and is only offered for trips up to 5 km (`PUSH_BIKE_MAX_KM` in `live_routes.py`; a note explains when it is hidden). E-scooter and e-bike times use assumed speeds of 15 and 20 km/h, labelled as assumptions on the card. All three have 0 kg tailpipe CO2 with the note "No tailpipe emissions; charging and manufacturing not counted" (manufacturing only for the push bike), so they take part in the CO2 lines, the Lowest CO2 badge, the CO2 sort, trip logging and the dashboard. They have Google cycling steps for the step list and for live directions. E-scooter and e-bike options show an estimated hire cost (an assumed $1 unlock plus 45c a minute at the assumed speed, editable in Settings) that counts towards the budget and the Cheapest sort, and their detail sheet and next steps have "Open Lime" and "Open Neuron" buttons (app store listings on a phone, the operators' pages on a computer). No provider availability or price feed exists, so the push-bike cost is "not checked" and panic mode never recommends a cycle option; check an operator's app and local rules before travelling.

### Live data and disruption handling

- **Weather widget, weather page and walking warning:** the start screen shows current weather and the next hours from the Open-Meteo forecast; tapping it opens a weather page with wind and direction, humidity, rain chance, UV, sunrise and sunset, the next 24 hours, the next 7 days and an interactive RainViewer rain radar for the last two hours (play and time slider). After "Latest" the slider and play loop continue into the next hour as "Forecast" steps from Open-Meteo's 15-minute rain forecast, shown in a "Next hour" bar chart under the radar while the map keeps the latest radar image, because RainViewer no longer offers future radar. Bad weather (precipitation chance of 50% or more or 0.5 mm per hour or more, thunderstorm or heavy rain codes, apparent temperature of 35 degrees or more, or gusts of 50 km/h or more) adds a warning, and an option with 5 or more walking minutes shows a walking-in-the-weather warning. The widget uses Brisbane weather unless location access was already granted.
- **Exact lines from static GTFS:** each Google transit step is matched to Translink route IDs, stop IDs and, where TripUpdates allow, the exact trip, so alerts and delays match by route ID. The keyword matcher remains the fallback while the static data is loading or a step is unmatched.
- **Live vehicles and delay status:** each transit step shows "On time", "N min late", "N min early", "Cancelled" or "No live data", refreshed every 15 seconds on the next-steps and directions screens, with the vehicle position on the map before boarding. "On time" and "early" are reported only for an exactly matched trip; otherwise only a route-wide median delay of a minute or more is shown.
- **Live in-app directions:** a navigation screen follows the traveller's GPS along the chosen trip with the next maneuver and distance for walking and driving, boarding and alight countdowns for transit legs, a step list, optional voice prompts, a screen wake lock, skip step and re-centre, and a "Re-plan from here" prompt after about 10 seconds more than 60 m off a walking or driving step. "Open in Google Maps" stays as a secondary link.
- **Journey disrupted? (Panic mode):** a large button on the home screen, reworded from "Panic mode" to name journey disruption ("Get the best working way there now — on time first, no decisions."; the screen's top label reads "Best way now"). It opens the screen that returns one recommendation using only options with no active Translink alert, on time first, public transport preferred, then least effort. When the least-effort option would leave under 10 minutes before the deadline (`CLOSE_BUFFER_MIN` in `live_routes.py` and `offline.js`, a team assumption), the option with the most spare minutes wins and effort only breaks ties (2026-10-27; it was least effort, labelled "Fastest way now"). The answer shows its spare time against the deadline ("3 min before your 8:55 am deadline", with "tomorrow" when a passed "by" time moved to the next day) and names the disrupted options it avoids ("Avoids the 412 · Translink alert · Simulated"). While it searches, the button reads "Checking routes and live services…" (the Plan a trip button too). "See other options" opens the results on top of the answer, so Back returns to it without another search, and the answer's card carries a "Best way now" badge (2026-10-27).
- **Translink alerts and watch:** home-screen alerts, a searchable alerts sheet (long alerts are clamped with "Show more", which opens the whole alert) and, while the app is open, a once-a-minute check of the chosen trip with "See my alternatives".
- **PWA install and background push monitoring:** the app has a manifest, icons and a service worker (offline app shell for every page including `/terms`, `/privacy` and `/about`, network-first API reads). On a chosen trip, "Watch this trip in the background" asks for notification permission and sends a Web Push subscription and the trip's route IDs to the server. A server thread checks every 60 seconds and sends one push per new disruptive alert or cancellation on those routes; opening the notification re-plans the trip avoiding the disrupted lines. A watch expires 30 minutes after the deadline (3 hours with none). Settings and the home screen offer an "Install Reroute" button where the browser supports it, and on iPhone a sheet explains Share, then Add to Home Screen.
- **Refresh live data:** a home-screen button calls `POST /api/sync` to refresh alerts, vehicles and weather, shows a skeleton, then a success or error banner that dismisses after 3 seconds.

### Sharing and sustainability

- **Share / QR:** a Share sheet shows a QR code (from `GET /qr.svg`, which encodes `PUBLIC_URL` or the address the request came to), the link, a copy button and the system share sheet where available.
- **Ride board:** offer car seats or start a split Uber. Posts match when the start is within 2 km, the destination is within 2.5 km and departure is within 45 minutes. It stores only rounded points, no contact details, expires 30 minutes after departure and is visible only to people using the same server.
- **CO2 focus on results:** each option card has a dedicated CO2 line (for example "1.2 kg CO2 less than driving", with the trip's own figure against the same journey driven alone), the lowest-CO2 option carries an outline "Lowest CO2" badge, and one muted line above the cards says how the greenest option compares with driving. Arrival comes first (2026-10-27): the badge and that line consider only options that arrive on time (when a deadline is set) with no disruption, and say so when they leave others out. Options that miss the deadline or are disrupted show their CO2 as one muted line on the card and a neutral strip in the detail sheet. When no option meets every limit, one line above the cards says so and names the options that still arrive on time. Everything derives from the per-option estimate, the driving baseline and the factors in Settings; the card field can be hidden in Settings.
- **CO2 on next steps and logging:** the next-steps screen states the trip's CO2 saving, and logging the trip ("I'm taking this trip") changes it into a success state with the new monthly total against the goal.
- **Impact button and Impact Dashboard:** a leaf button in the home header shows this month's CO2 avoided and goes straight to the dashboard. With no trips logged it shows only the empty-state message. Otherwise it has a hero total labelled "Estimated CO₂ avoided", the money saved ("Unknown" when every logged saving is unknown), the trips planned and how many were not by car, a monthly CO2 goal with a progress ring (the team's default of 10 kg, named as such until changed in Settings), an "about the CO₂ of driving N km" line computed from your own car settings with the assumption stated, a weekly streak of finished weeks with no driving of your own car, a breakdown by mode, the six-month charts and recent trips. All numbers come from the trips logged on this device, which are planned trips, not checked travel (2026-10-27). History stays in the browser.
- **Saved places:** Home and Work/Uni can be edited, and up to 10 more can be added, edited and deleted in Settings (a name such as Gym or Mum's plus an address with the same autocomplete). They appear as quick-fill chips in From and To, as Journey disrupted? destination chips and in the suggestion list. Older saved Home and Work values are migrated automatically.

### Demo mode

The Demo mode row in the side menu (tap the logo on the home screen) or in Settings opens a menu for an investor walkthrough: weather (Live, Clear, Rain, Storm, Heatwave), disrupted mode (None, Train, Bus, Ferry, Light rail, All public transport), traffic (Live, Heavy, Crash on route), running late (0, 5, 10 or 20 minutes added), start point (current location or a preset Taringa Station to UQ St Lucia trip), a simulated journey that plays the directions back at 25 times speed instead of using GPS, and "Send test disruption push in 10 s". A Demo mode pill stays visible, and every simulated value is labelled "Simulated". **Only in demo mode**, each search shows the Google API requests it made and an approximate cost in US dollars, calculated from list prices in `google_api.py` (checked 2026-10-21, before Google's free monthly usage caps). In the developer check, a first demo search cost about US$0.10.

### Settings

A slide-in Settings panel covers theme (Auto, Light, Dark) and reduce motion; ways to travel; fuel use, fuel type and fuel price ("Live average" or manual); assumed e-scooter and e-bike hire prices (shown when either mode is on); typical parking cost; a flat public-transport fare used when Google returns none (default $0.50, an assumption to check); default limits; toggles for each card field; saved places (add, edit and delete up to 10 places beside Home and Work/Uni); watch-trip options; the monthly CO2 goal; editable CO2 factors; demo mode; install; share; clearing the impact history; and a link to the fictional interview scenario.

## Stack decision

The server is now Flask. The design-system brief ([`design-system.md`](../../docs/design/design-system.md)) specified Flask, production deployment needs a proper WSGI server (gunicorn) rather than the standard-library development server, and Flask removes the hand-written routing and header handling that v2 needed. The front end stays plain HTML, CSS and JavaScript (`index.html`, `app.js`, `app.css`) with no build step. The v2 reasons for rejecting Streamlit still apply. Production runs `gunicorn -w 1 --threads 8 server:app`, with one worker because the push monitor thread, the static GTFS loader and the feed caches live inside the process. `python server.py` still works for local development.

## Limitations

- No participant has tested Reroute (v3 with the refinements), and nothing has been deployed.
- Several things have not been tried: a real phone, iPhone and Safari, HTTPS hosting, the container and hosting configuration, real outdoor GPS directions, the wake lock, voice prompts, notification taps and bus bearing rotation.
- Push was verified only in headless Edge. Background monitoring needs the server to be running, a secure origin and notification permission, and it stops when a free host sleeps.
- The service worker serves the app shell cache-first, so `VERSION` in `sw.js` must be bumped for every deploy.
- Very short Google walking steps can clutter the step list.
- The vehicle marker shows before boarding but not while riding. Bearing is usually missing from Translink's vehicle feed.
- "On time" and "early" appear only for an exactly matched trip; otherwise live status is "No live data" unless the route as a whole is late. Matching of train lines remains imperfect.
- The weather widget uses Brisbane weather unless location access was already granted.
- Traffic delay is an estimate from QLDTraffic events; the numbers (5 minutes, 2 minutes, 20-minute cap) are team design assumptions.
- API costs shown in demo mode are list-price estimates before free monthly usage, and are shown only in demo mode.
- The Terms, Privacy and About pages need review against the final hosting and operating arrangements before public deployment. The rate limits (`PLANB_PLAN_LIMIT_PER_HOUR` default 40, `PLANB_DAILY_GOOGLE_CAP` default 50 and `PLANB_DAILY_AUTOCOMPLETE_CAP` default 500) reduce but do not remove the risk of Google charges.
- The CO2 factors and the $0.50 flat fare are assumptions, not verified values.
- Parking is the list of car parks Google returns, not live space availability, and parking prices are not available from Google.
- E-scooter and e-bike hire availability is not provided, and their hire cost is an estimate from assumed prices ($1 unlock and 45c a minute by default), not Lime's or Neuron's real prices, which are shown only in their apps. Times use assumed speeds (15 and 20 km/h) on a cycling route, and their CO2 counts tailpipe emissions only.
- The rain radar depends on RainViewer's free API (personal and educational use, tiles up to zoom 7, about 100 requests a minute per address, no future frames, no guaranteed availability). The next hour after the radar is Open-Meteo's model forecast, not radar; for Australia its 15-minute steps are interpolated from hourly data, so timing within the hour is approximate. The map picker (including the enlarged place pin and the dragged pin) and the radar map were not shown in the 2026-10-23 or 2026-10-26 developer checks, because no working browser map key was available; check them with the deployed browser key on a phone.
- The app does not show an Uber price. Rideshare cost is unknown unless a rider enters the estimate they saw on the ride board.
- The ride board works on a single server, is unmoderated, and does not address identity, safety checks or moderation.
- The impact history is stored per browser and is lost if browser data is cleared.
- The 10 kg monthly CO2 goal is a default the team chose, not a recommended target. The "about the CO₂ of driving N km" figure is your logged CO2 saving divided by the emissions per km implied by your Settings (litres per 100 km times kg of CO2 per litre); it is an estimate, not a measurement. The weekly streak counts only trips logged in the app, treats Uber and shared rides as not driving your own car, and uses Monday to Sunday weeks in Brisbane time. The current week counts only once it ends, but a driving trip logged this week ends the streak straight away.
- Added places are limited to 10 plus Home and Work/Uni. Deleting a place needs two taps. Places are stored only in this browser.
- Renaming did not regenerate the logo or the icon files. The name Plan B remains in the interview scenario and in internal identifiers (see the name change section above).
- The clear (x) buttons, saved-place editor and dashboard were not tried on a real phone or with a screen reader.
- The focus management above was checked with the keyboard in headless Chrome on 2026-10-27, not with a screen reader or on a phone, and the full-screen map was checked only through its action, because no browser map key was available. Contrast ratios are calculated from the tokens, not measured on a device.
- Google Routes estimates are not confirmed disruption notices, guaranteed arrival times or booking options. Verify services and directions before leaving.

## Offline maps

The saved-journeys snapshots added on 2026-10-24 were removed on 2026-10-26: public transport services and timetables change from day to day, so a saved journey goes out of date. They were replaced by downloading an area for offline use (the [offline area log](../../docs/product/reroute-offline-area-log-2026-10-26.md) records how it was built and checked; the old [offline journeys test card](../../docs/discovery/experiments/test%20cards/test-card-offline-journeys.md) is marked withdrawn).

- **Download an area:** Settings → Offline info → Download an area for offline use opens a map with a rounded box in the middle; everything outside the box is dimmed and the box's size is shown. Move and zoom the map so the box covers the area (from 0.5 km up to 8 km a side and 40 km², inside South East Queensland), choose 1, 3 or 7 days of timetables and tap Download Information. The server sends an OpenStreetMap extract (the base map, suburb and major place names, significant places such as stations, hospitals and universities, and the road and path network) and the Translink scheduled services inside the box for those days; the app adds the saved places inside the box and stores everything in this browser's IndexedDB. A dense 6 × 6 km inner-Brisbane area is about 5 MB stored (under 1 MB transferred, gzipped). Large areas can take about a minute because the Overpass API is slow; the app waits and retries when the server asks it to.
- **Use Offline Maps:** when Reroute's live data cannot be reached, a banner says you're offline and offers Use Offline Maps. Offline mode starts only when you tap it, and a banner stays visible while it is on ("Offline maps · not live", with Exit or, once back online, Use live data).
- **What works offline:** Plan a trip and Journey disrupted? search the downloaded area (suggestions come from its places, stops, streets and your saved places; Current location and Choose on map still work), with walking, cycling, e-scooter, e-bike and driving routes on the OpenStreetMap network and scheduled public transport with at most one transfer. Results, next steps, the route maps, the map picker and live directions use an offline map drawn from the downloaded data. Every offline result is labelled as an estimate: no live delays, disruptions, alerts, traffic, weather, fares from Google, Uber, shared rides or push notifications.
- **Storage:** one area at a time; Settings shows its size, stop count, timetable dates and download date, and can preview it or delete it.
